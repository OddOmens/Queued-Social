🎯 The Discovery

Found the issue! Threads OAuth requires client_secret in the authorization URL, which is unusual for OAuth 2.0 flows.

Most OAuth flows only require client_secret during token exchange, but Threads requires it in the authorization step too.

⚠️ Security Note

Including client_secret in the authorization URL is unusual and potentially less secure because:

  • The secret appears in browser history
  • It can be logged by web servers
  • It's visible in network requests

However, this appears to be how Threads OAuth is designed. Meta may have additional security measures in place.
